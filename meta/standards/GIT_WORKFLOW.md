# Git Workflow - Deep Study

این فایل روش پیش‌فرض کار با Git در پروژه Deep Study را مشخص می‌کند.

## branch اصلی

- branch پیش‌فرض و canonical پروژه: `main`
- در این پروژه وقتی گفته می‌شود «branch اصلی» یا «master»، منظور همان `main` است مگر کاربر صریحاً چیز دیگری بگوید.

## رفتار پیش‌فرض

برای تغییرات معمول پروژه:

- مستقیم روی آخرین نسخه `main` کار کن.
- branch جدا نساز.
- Pull Request نساز.
- تغییرات تأییدشده را مستقیم روی `main` commit کن.

این رفتار برای تغییر سندها، promptها، state، syllabus، source درس‌ها، workflowها و artifactهای تأییدشده پیش‌فرض است.

## چه زمانی branch یا PR مجاز است؟

فقط وقتی کاربر در همان درخواست صریحاً branch یا Pull Request بخواهد.

اگر GitHub به دلیل branch protection یا permission اجازه نوشتن مستقیم روی `main` نداد:

1. خطا را واضح گزارش کن.
2. خودکار branch یا PR نساز.
3. فقط اگر کاربر بعداً صریحاً خواست، مسیر branch/PR را اجرا کن.

## قبل از هر write

- آخرین نسخه فایل را از `main` بخوان.
- SHA فعلی همان فایل را بگیر.
- تغییر را روی همان نسخه اعمال کن تا اصلاحات جدید دیگران overwrite نشوند.
- برای چند تغییر پشت سر هم روی یک فایل، از SHA جدیدی که write قبلی برگردانده استفاده کن.

## GitHub Actions

- workflowهای معمول پروژه باید روی push به `main` کار کنند.
- workflowهای promotion که artifact تأییدشده را commit می‌کنند باید همان commit را روی `main` بزنند.
- موفق‌شدن build به‌تنهایی اجازه انتشار PDF را نمی‌دهد؛ approval و QA contract همچنان اجباری است.

## ایمنی تاریخچه

- force push به `main` ممنوع است مگر کاربر صریحاً درخواست کند و اثر آن روشن باشد.
- تاریخچه موجود را بی‌دلیل rewrite نکن.
- حذف یا rollback تغییرات قبلی فقط با دلیل روشن انجام شود.

## override کاربر

دستور صریح کاربر در همان task بر این default مقدم است. مثال: اگر کاربر گفت «برای این تغییر branch و PR بساز»، فقط همان task با branch/PR انجام می‌شود و default کلی پروژه عوض نمی‌شود مگر کاربر صریحاً بخواهد.
